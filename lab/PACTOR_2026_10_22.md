# PACTOR-I Implementation — 2026-10-22

Phase 12 PACTOR-I: FSK modem at 100/200 bd, memory ARQ, Huffman compression,
and a text terminal (`--modem pactor`).

## Sources

All from published documents and GPL source — clean-room, no vendor disassembly:

- **hfterm pactor.c / pactor.h** (Thomas Sailer, GPL): CRC table (reflected
  CRC-CCITT, init 0xFFFF, complement, good residue 0xF0B8), 128-entry Huffman
  table, CS1–CS4 (12-bit codes with Hamming distance ≥ 8), status byte layout,
  and packet format.
- **ARRL PACTOR page**: protocol overview, speed fallback, memory ARQ concept.
- **NB6Z pactor.htm**: detailed frame timing (1.25 s standard, 1.40 s longpath),
  header bytes (0x55/0xAA), idle character (0x1E).
- **Helfert/Rink (DL6MAA/DL2FAK) PACTOR-II article** (qsl.net/f5ru): ARQ state
  machine description, speed-change rules.
- **Wavecom monitoring help PDF**: PACTOR-I signal parameters (center frequency,
  shift, baud rates).

Research notes with full URLs: `lab/PACTOR_RESEARCH_2026_10_22.md`.

## Packet format

200 bd: 20 data + 1 status + 2 CRC = 23 bytes (184 bits + 8 header = 192 total).
100 bd: 8 data + 1 status + 2 CRC = 11 bytes (88 bits + 8 header = 96 total).

Status byte: bits 0–1 counter, bit 2 Huffman flag, bit 6 break-in, bit 7 QRT.

## Bugs fixed

1. **CRC residue**: `GOOD_CRC = 0x0F47` was the inverted residue; corrected to
   `_GOOD_RESIDUE = 0xF0B8` (raw residue before complement).
2. **Huffman encoder bit packing**: rewrote to byte-indexed packing matching
   hfterm's approach.
3. **Loopback `pkt_bytes`**: was 24/12 (off by one from the actual 23/11 packet
   size), causing `best_phase` to overshoot the discriminator buffer.
4. **`best_phase` boundary**: when the burst starts near the beginning of the
   discriminator output, all phases except 0 could overshoot the cumsum array.
   Fixed by starting the cumsum `margin = min(first, spb)` samples earlier.

## What's not implemented

- **PACTOR-II/III/IV**: generator polynomials, puncture patterns, interleaver,
  and 40-bit CS codes are unpublished. SCS took down their protocol PDF. Deferred
  to phase 15 (reverse engineering from recordings, if available).
- **G-TOR**: Kantronics' DCC paper describes the Golay coding but the header and
  ACK format details are insufficient for interop. Also deferred to phase 15.
- **Live ConfBridge test**: not yet done; the modem is ready for it.
