# Phase 12.0: AMTOR / SITOR (CCIR 476), ARQ and FEC — 2026-10-22

Built from the public ITU-R M.476-5 (fetched from itu.int; the code table and every protocol rule used below are in
it) -- no vendor material. `ham-modem --modem amtor --mycall CALL --text-pty PATH | --text-tcp PORT` on any 8 kHz leg.

## What is implemented (`hammodem/amtor/`)

* `code.py`: the 35 constant-weight 7-unit codes, letters/figures text conversion; checked against the ITU table
  (A = BBBYYYB, LTRS = YBYBBYB, FIGS = YBBYBBY, CS1/2/3, idle alpha/beta, signal repetition).
* `fsk.py`: 100 baud FSK, 170 Hz shift about 1700 Hz (mark = higher tone), phase-continuous; discriminator front end.
* `fec.py` (mode B / SITOR-B, collective): each character sent twice, the RX copy five slots (280 ms of other
  characters) after the DX copy; phasing 2/1 pairs at the start, idle beta between, three idle alpha ends the
  emission. The receiver finds bit phase and character alignment from the 4-of-7 check alone, pairs DX/RX copies
  and counts characters saved by the RX copy (`corrected`) and lost in both (`lost`).
* `burst.py` + `arq.py` (mode A / SITOR-A): 450 ms master-clocked cycle, 3-character blocks (210 ms), 70 ms control
  characters, block numbering 1/2 with CS1/CS2, repeat on a mutilated reply with a block of three RQ, the two-block
  selective call (c1 RQ c2 / c3 c4 RQ) with a four-letter selcal derived from the callsign (W1AW -> WWAW,
  G3PLX -> GPLX), two identical control signals to start, change-over (FIGS + ? then CS3, idle beta/alpha/beta,
  RQ), end of communication (idle alpha, up to four tries), time-outs (32 cycles calling, 64 cycles to standby).
* `tnc.py`: text terminal (pty or TCP): type to send, `/connect CALL`, `/fec`, `/arq`, `/turn`, `/disconnect`,
  `/status`, a line ending in `+?` turns the link around.

## Limits and notes

* The master's 240 ms listening window must hold the slave's reply delay (`--amtor-reply`, default 50 ms) plus the
  audio round trip plus the 70 ms control character: round trip up to ~100 ms at the default.
* Selective FEC (inverted code) is not implemented; the selective-call number is the four-letter selcal only.
* No interop against real AMTOR equipment was possible here (no peer available): behaviour follows the Recommendation
  and the ITU code values; compatibility with deployed terminals (and the 1500 Hz audio centre some use, `shift`/
  `center` are parameters) is untested.

## PACTOR-I and G-TOR: what is public (researched 2026-10-22, not implemented)

Both were looked up for phase 12; the published material is enough to describe them but not to interoperate.

* **PACTOR-I** (Wavecom overview, NB6Z page): 200 Hz tone spacing, 100 and 200 baud, 1.25 s cycle (packet 0.96 s =
  96/192 bits, control signal 0.12 s = 12 bits of 10 ms, 0.29 s gap), packet = header + 8/20 data bytes + status byte +
  CRC16 (CCITT polynomial, over everything but the header), memory ARQ by summing soft bits, shift toggled each cycle,
  control signals CS1 4D5, CS2 AB2, CS3 34B, CS4 D2C (hex, 12 bits, LSB right), Huffman compression (2-15 bit codes).
  **Missing**: the header bit layout, status byte bit positions, the Huffman table, idle packet, exact call/sync
  packet format. Without them a modem would only talk to itself.
* **G-TOR** (Kantronics; DCC 1994 evaluation paper, NB6Z page, Wavecom): 100/200/300 baud FSK, 2.4 s cycle (1.92 s
  frame + 0.48 s for the 100-baud acknowledgement), frame = 21/45/69 data bytes + 1 status byte + 2 CRC bytes =
  168/360/552... bits (the 300 baud frame is 48 twelve-bit words), extended Golay (24,12) with a parity frame the same
  size as the data frame, bit interleaving over the whole frame ("12 bins of 48 bits"), type-II hybrid ARQ (on a NACK
  the parity frame is sent; inverting the parity gives the data bits, so two transmissions give three chances to pass
  the CRC), five ACK kinds (ok, error, speed up, speed down, changeover) sent as error-tolerant patterns, Huffman +
  run-length compression. **Missing**: the ACK bit patterns, status byte layout, CRC polynomial, link-frame format,
  tone pair/shift, interleaver ordering, compression tables (all in Kantronics' booklet / the 1994 QEX article).

Decision: not implemented; the generally useful parts (extended Golay codec, type-II hybrid ARQ with parity
retransmission) can be added later as our own "Golay ARQ" mode if wanted, clearly not wire-compatible.
