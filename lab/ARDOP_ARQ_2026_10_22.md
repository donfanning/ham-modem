# Phase 10.3 / 10.0: ARDOP ARQ sessions, live against ardopcf — 2026-10-22

`hammodem/ardop/arq.py` (`ArqStation`): ardopcf's ARQ state machine ported (ARQ.c `ProcessRcvdARQFrame`,
`GetNextARQFrame`, `SendData`, `Gearshift_9`, `IRSNegotiateBW`; the SoundInput.c IRStoISS / BREAK shortcuts;
ARDOPC.c timers) with the spec's Appendix D rules. It is clocked only by the audio passing through `process()`, so
two stations can be wired together offline; host events use ardopcf's host-interface strings.

## Live interop with ardopcf (lab/ardop: run_peer.sh, relay.py, alsa_tap.c, live_arq.py)

ardopcf runs in a container on the isolated lab network (172.31.73.40, no host ports); its audio is UDP to the host
(20 ms blocks, 12 kHz) and our station runs in lockstep with the relay's real-time clock. ardopcf is driven over
its own host interface (8515/8516) exactly as Winlink clients drive it.

| run | session | result |
|---|---|---|
| ardopcf calls us, 1000 B to us, 300 B back, ardopcf disconnects | 500 Hz | both intact; IDLE -> our BREAK -> we become ISS; DISC/END/ID; 64 s |
| we call ardopcf, 600 B to it, 1000 B back, we disconnect | 500 Hz | both intact; ardopcf BREAKs in; 64 s |
| ardopcf calls us, 8000 B to us, 4000 B back | 2000 Hz | both intact; 120 s |
| we call ardopcf, 8000 B to it, 300 B back, drive 50% | 2000 Hz | both intact, 17/17 frames ACKed first time, no ardopcf input warnings |

Gear shifting toward ardopcf stops at 4PSK.2000: ardopcf rates even clean 4PSK at ~85 (its phase estimator; ours
says ~99 for the same frames) and its own threshold to leave 4PSK.2000 is > 85 -- two ardopcf stations behave the
same. At full drive (ardopcf's own TX level) ardopcf warns `INPUTPEAKS -32700 32700`; `ArqStation(drive=0.5)`
removes that.

### Getting audio in and out of ardopcf without a sound card (three wrong turns)

ardopcf only does ALSA. Capture works with ALSA's `file` plugin (`infile` = a FIFO the relay fills in real time).
Playback did not:

1. `file` plugin to a FIFO with a one-page pipe for backpressure: ardopcf's writes stalled, PTT lasted twice the
   frame.
2. Unthrottled FIFO: PTT right, but every sample arrived only at PTT off -- the `file` plugin always holds back one
   whole ALSA buffer (ardopcf leaves it at the `null` device's default, longer than a frame).
3. Buffer capped to 100 ms with an LD_PRELOAD shim (480 frames deadlocks ardopcf, whose writes are 1200 frames):
   frames arrived on time except their last buffer, which the plugin flushes only on drain/close -- which ardopcf
   does not do between frames. Short control frames (IDLE) lost their frame-type symbols (type score 0.63 < 0.7),
   so the first live session moved 1000 bytes and then stalled at ardopcf's IDLE.

Fix (`alsa_tap.c`): playback goes to a plain `null` PCM and an LD_PRELOAD `snd_pcm_writei` wrapper copies every
accepted frame straight into the FIFO, unbuffered; the relay paces it (60 ms pre-roll per burst). ardopcf times PTT
from its own sample count, so its timing is real.

## Offline (tests/test_ardop_arq.py and scratch harnesses)

Two stations back to back at 8 kHz: connect, transfer, IDLE/BREAK turnaround, disconnect; 25% of transmissions
silently dropped (repeats, no duplicates); incompatible bandwidth (ConRejBW); unanswered call (5 ConReqs, FAILED);
PING/PingAck. Through the HF simulator: CCIR moderate at 15 dB -- 4 NAKs, 2 shift-downs, 3 shift-ups, data intact;
CCIR poor at 10 dB -- 9 repeats, intact.
